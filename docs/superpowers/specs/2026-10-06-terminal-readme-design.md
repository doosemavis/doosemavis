# Terminal-style profile README — design

**Date:** 2026-10-06
**Branch:** `feat/terminal-readme`
**Inspiration:** [How I Built an Animated GitHub Profile README](https://www.avivashishta.com/blog/build-animated-github-profile-readme) (Avi Vashishta, July 2026). Same core technique (all motion lives in self-contained SVGs generated by scripts), adapted to this profile's content and constraints.

## Goal

Replace the current README (gradient banner, logo cards, hosted stats widgets) with a terminal-themed page: a self-typing ASCII portrait, a neofetch-style info card, a live contribution heatmap refreshed daily, a typing tagline, and current featured projects.

**Success criteria**

1. The rendered profile loads zero images from third-party services. Every image is a committed SVG in this repo.
2. The heatmap reflects real contribution data and updates daily without manual work.
3. Every animation plays once and holds its final frame (only exception: the tagline cursor blinks). With `prefers-reduced-motion: reduce`, every SVG shows its final frame immediately.
4. The source photo never enters the repository.
5. Editing any text (tagline, card lines, project blurbs) means editing `profile.json` only.

## Constraints

- GitHub strips `<script>`, inline `style`, and external CSS from READMEs; it renders `<img>`-embedded SVGs and runs CSS keyframe animations inside them.
- `<img>`-embedded SVGs cannot load web fonts. Text uses the stack `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`.
- Vertical spacing in the README is only controllable with `<br>`. `<h1>`/`<h2>` draw an underline rule; section prompts use `<h3>`.
- Two images on one row requires a `<table>`.
- GitHub's camo proxy caches images. The heatmap keeps a stable filename; if a stale image ever sticks, renaming the file busts the cache.

## Components

Each script is a small CLI with one job, reading `profile.json` and/or `data/` and writing files in `assets/`. Pure functions (parsing, stats, SVG string building) are separated from file I/O so they can be unit-tested.

| Script | Runs | Input → Output |
|---|---|---|
| `svg_common.py` | imported | palette, font stack, `esc()` XML escaping, `svg_doc()` wrapper that injects the shared `<style>` incl. the reduced-motion rule |
| `make_tagline.py` | CI | `profile.json` → `assets/tagline.svg`: prompt + `echo "<tagline>"` types in character by character, block cursor blinks after |
| `make_info_card.py` | CI | `profile.json` → `assets/info-card.svg`: title bar, `moose@github` header + rule, colored key/value rows fading in on a stagger, swatch row last |
| `make_project_cards.py` | CI | `profile.json` → `assets/project-<slug>.svg`: title bar `~/projects/<name>`, wrapped blurb (max 2 lines), language dot + name |
| `fetch_contributions.py` | CI | `github.com/users/doosemavis/contributions` → `data/contributions.json` (days + derived stats) |
| `render_heatmap_svg.py` | CI | `data/contributions.json` → `assets/contrib-heatmap.svg` |
| `prep_photo.py` | local only | photo path → `.portrait/prepped.png` |
| `make_ascii_svg.py` | local only | `.portrait/prepped.png` → `assets/ascii-portrait.svg` |

### Contribution data

- Fetch with `requests` (timeout 20s, browser-like User-Agent). Parse with BeautifulSoup: each `td.ContributionCalendar-day` gives `data-date`, `data-level` and an `id`; the matching `tool-tip[for=<id>]` text gives the count (`"No contributions…"` → 0, `"N contribution(s) on…"` → N).
- Derived stats: `total`, `current_streak` (consecutive days with count > 0 ending today, or yesterday if today is still 0), `longest_streak`, `best_day` (`{date, count}`).
- **Validation (fail loud, never overwrite good output with bad):** ≥ 350 days parsed, dates contiguous with no gaps or duplicates, every level in 0–4, every count ≥ 0. Any failure → non-zero exit, nothing written.

### Heatmap

- 53 columns × 7 rows of rounded cells (`rx=2`), Sunday-first rows to match GitHub; month labels above, `Mon/Wed/Fri` labels at left.
- Reveal: each cell fades/slides in with a delay proportional to `column + row` (diagonal sweep), ~2.5s total, then holds.
- Footer: `1,045 contributions in the last year · current streak N days · longest N days · best day N (Mon D)` plus a `Less ▢▢▢▢▢ More` legend.

### ASCII portrait

- `prep_photo.py`: rembg background removal → composite subject onto **black** → grayscale → OpenCV CLAHE (clip 2.0, 8×8 tiles) → crop to the subject's bounding box with 6% padding, square → save.
- `make_ascii_svg.py`: downsample to a 90-column grid, rows scaled by the monospace aspect (~0.5) → ~45 rows. Ramp `" .`:-=+*cs#%@"` ordered sparse→dense; **brightness maps to density** (black background → space, bright skin → dense glyph) because glyphs render light-on-dark. Single fill `text` color.
- Each row is one `<text>` with `xml:space="preserve"` and a fixed `textLength` so alignment never depends on which monospace font the viewer has.
- Animation: each row is revealed left→right by a CSS-keyframed `clip-path: inset()` (CSS, not SMIL, so the shared reduced-motion rule disables it), rows staggered top→bottom, a block cursor riding the leading edge; ~3s total, prints once and holds.
- `.portrait/` and common photo extensions are git-ignored; the original photo stays outside the repo.

## Daily automation

`.github/workflows/update-profile-art.yml`

- Triggers: `schedule` (`17 6 * * *`), `workflow_dispatch`, and `push` to `main` filtered to `profile.json` and `scripts/**`.
- `permissions: contents: write`.
- Steps: checkout → setup-python 3.11 → `pip install -r scripts/requirements.txt` (requests, beautifulsoup4, pytest only) → `pytest` → run the four CI scripts → `stefanzweifel/git-auto-commit-action@v5` committing `assets/*.svg data/contributions.json` with message `chore: refresh profile art [skip ci]`.
- Tests run before rendering, so a broken generator fails the job instead of committing a broken SVG. GitHub emails the owner on failure; the last good SVGs stay live.

## Testing

pytest, written test-first.

- **Parser:** a saved copy of the contributions HTML (`tests/fixtures/contributions.html`) → asserts day count, a known date's count/level, and the fixture's total.
- **Stats:** hand-built day lists covering an empty year, a streak ending today, one ending yesterday, a broken streak, and ties for best day.
- **Validation:** gap in dates, duplicate date, out-of-range level, short calendar → each raises.
- **SVG output:** every generator's output parses as XML, has the expected `viewBox`, contains the reduced-motion rule, and escapes `&`/`<` in content.
- **ASCII:** a synthetic gradient image maps black → space and white → `@`; row count/width match the grid; every row has the same `textLength`. These tests use `pytest.importorskip` for Pillow/numpy, so they run locally and skip in CI (which installs only the light requirements).
- **Animation rule:** all generators animate with CSS keyframes only (no SMIL), so the shared reduced-motion rule covers everything.
- **Manual:** view each SVG in a browser (animation + reduced motion) and the branch README on github.com before merging.

## Delivery

Work on `feat/terminal-readme`, open a PR to `main`. The owner previews the branch README on GitHub, then merges. After merging, run the workflow once via `workflow_dispatch` to confirm the bot commit lands.

## Out of scope

Profile view counter, monthly totals, looping/glow effects, light-mode variants (all SVGs carry their own dark background), automating the portrait in CI.
